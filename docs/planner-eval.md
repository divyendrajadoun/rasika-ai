# Planner evaluation

How we judge the plans Claude produces (SPEC Phase 5), and the scores on the current test reels.
Re-run with `pnpm planner:eval` (see the bottom of this file) whenever the prompt or the schema
changes.

## Rubric (each 0–5, averaged per reel)

| Criterion               | 5 looks like                                                                 | 0 looks like                                   |
| ----------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------- |
| **Anchor accuracy**     | every element starts on its word (≤ 0.15 s); `anchorWordIndex` set; nothing enters before the word is spoken | elements float free of the speech              |
| **Layout variety**      | a mode switch at least every 8 s and something new on screen every ≤ 6 s; full/card/pip/zoom all used where the speech allows | one layout for 20 s, or churn with no reason   |
| **Text completeness**   | every poster line reads as a complete thought in the speaker's own words; no fragments, no cut clauses | "and the", "of", dangling halves               |
| **Image-label honesty** | each image used for what its label says, on the word that names it; no image → pattern/typography | a photo of the kitchen labelled "balcony"      |
| **Zone discipline**     | poster text in the free zone above the head, ends above y 680 in dark modes, cards never on the face, light tokens on the wall / ivory-gold on the stage | text across the face, maroon on maroon          |
| **Industry fit**        | the vocabulary and beats belong to this speaker (listing, clinic, kitchen…), not to the few-shot example | jewellery words in a real estate reel          |

Mechanical parts of the rubric are measured by `validatePlan` (anchor nudges, overlaps, zone
checks, rhythm warnings); the judgement parts (completeness, honesty, fit) are read by a person
from the on-screen text dump the eval script prints.

## Scores

Scored 2026-10-18 on the first run of the Phase 5 planner (Opus 5.5, one repair round allowed).
Mechanical columns come from the validator report; judgement columns from reading every on-screen
line (`plan-local` dumps them) and the rendered stills.

| Reel         | Anchor | Variety | Completeness | Honesty | Zones | Industry fit | **Avg** | Attempts / errors / warnings / auto-fixes |
| ------------ | :----: | :-----: | :----------: | :-----: | :---: | :----------: | :-----: | ----------------------------------------- |
| baisa_bling  | 5      | 5       | 5            | 5       | 4     | 5            | **4.8** | 2 / 0 / 0 / 5 (4 font shrinks, 1 nudge of 0.44 s) |
| realtor_3bhk | 5      | 5       | 4            | 5       | 4     | 5            | **4.7** | 1 / 0 / 1 / 7 (6 font shrinks, 1 nudge of 0.16 s) |
| doctor_sleep | 4      | 5       | 3            | 5       | 4     | 5            | **4.3** | 1 / 0 / 3 / 4 (3 shrinks, 1 nudge of 0.40 s) |

Per-criterion notes:

- **Anchor** — every element carried an `anchorWordIndex`; the validator nudged one element per
  reel by 0.16–0.44 s. The doctor reel's "TELLS YOUR BRAIN" started 0.4 s early (nudged).
- **Variety** — 14 mode switches in 50 s on both synthetic reels, 21 in 90 s on Baisa; longest
  single layout 5.9 s (realtor kitchen card with chips), under the 6 s rule.
- **Completeness** — Baisa and the realtor read clean ("STOP SCROLLING / 3-BEDROOM FLAT / in Pune",
  "FLATS LIKE THIS / DO NOT STAY / more than two weeks"). The doctor reel has two borderline
  lines: "STILL / DIGESTING / should be resting" (the speaker's clause, but the subject is
  dropped) and "IF IT STILL / happens" (a lead-in that reads as a fragment on its own). Both are
  the speaker's words; the prompt's "read each line aloud" check did not catch them. Rule to add
  in the next prompt revision: a poster element must contain a verb *and* its subject unless it is
  a label.
- **Honesty** — no image was ever used for something it is not. Where the speech named things
  without a photo (gym, park, "the owner"), the planner used pattern plates, counters and chips.
- **Zones** — the validator shrank 3–6 lines per reel to fit the stage (the model over-sizes
  Anton by 10–25 %); on the doctor reel three lines used wall colours over the dark stage, which
  the validator now swaps automatically (added after this run).
- **Industry fit** — no jewellery vocabulary leaked into the realtor or doctor plans; the realtor
  got a `JUST LISTED` stamp, a lakhs counter and "message me 'balcony'" as the end card; the
  doctor got numbered chapters per reason, a one-degree counter and a calm `noir-minimal` end card.

Token cost (Opus): 10–17 K input per attempt with a 22.5 K cached prefix, 8–14 K output, 73–176 s.


## Observations

- A repair round happened only on the Baisa reel: the first answer had hard validator errors and
  the second answer cleared all of them (this run predates the `firstErrors` field in the report,
  so the exact list was only in the worker log; later runs keep it).
- The planner reproduces the few-shot's structure closely when the input *is* the few-shot's reel
  (expected). On other reels it keeps the craft (hook → number → chapters → payoff → brand → end
  card) and none of the vocabulary.
- Synthetic reels have no detectable face, so the subject falls back to the centred default; the
  planner still kept text in the top zone. Real reels (Baisa) got a detected face box and the
  planner respected it.
- Whisper lower-cases and American-spells; the Haiku fix pass restores casing and British spellings
  before captions use the words (`transcript_fix.py`).

## Re-running

```bash
python -m rasika_worker.cli transcribe-local --audio <reel.mp4> --out words.json
python -m rasika_worker.cli plan-local --words words.json --video <reel.mp4> --images <dir> \
  --style <preset> --brand "<Name>" --industry "<industry>" -o out/plans/<name>.json
python -m rasika_worker.cli render-local --plan out/plans/<name>.json --words words.json --images <dir> --video <reel.mp4> -o out/<name>.mp4
```

`plan-local` writes the raw first answer (`*.raw.json`), the validated plan and the validator report
(`*.report.json`) with token usage, so prompt changes can be compared.
